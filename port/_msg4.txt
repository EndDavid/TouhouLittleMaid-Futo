Port the chisel and the statues (blocks, entities, renderers, item)

The milestone the manual was waiting on: ItemChisel carves a clay block into a
multi-block statue, and the statue can be burned into a garage kit. Two held-back
Patchouli entries are back (chisel_and_statues, garage_kit); the book is now 42
entries / 3 categories, validator 0 problems.

What was ported, all from the 1.18.2 sources:
- BlockStatue + TileEntityStatue: a statue is N statue blocks (1x1x1 / 1x2x1 /
  2x4x2 / 3x6x3). Every block has a block entity; only the core one renders and
  carries the maid NBT, the rest just remember where the core is and which blocks
  the whole statue occupies. Breaking or exploding any single block turns the
  whole thing back into clay (leaving orphan block entities behind would be
  worse than losing the statue).
- BlockGarageKit + TileEntityGarageKit: single block, holds a facing plus one
  entity NBT. Three ways in: place the item, right-click with any spawn egg,
  or let a *tiny* statue burn (only TINY is randomly ticking, so only it melts --
  upstream behaviour, not a bug).
- ItemChisel + ItemGarageKit, ItemFavorabilityTool-style: the chisel needs a
  photo in the off hand; it tries sizes big-to-small and takes the first whose
  footprint is all clay, costing size.ordinal()+1 durability.
- StatueBaseModel: the 48x2x48 pedestal plus four 45x7 flags. The coordinates are
  ~3x life size because renderToBuffer scales by 0.325; they are not typos.
- TileEntityStatueRenderer / TileEntityGarageKitRenderer / GarageKitItemRenderer.
- MaidRenderState enum, EntityMaid.MODEL_ID_TAG, EntityMaid.renderState,
  EntityCacheUtil (three caches; maids get one instance per block position or per
  item stack because GeckoLib bone state would otherwise bleed between statues).
- A dedicated GARAGE_KIT_TAB creative tab: one kit per loaded maid model.

Deviations forced by 1.18.2 / Fabric, each one deliberate:
- Rendering culling: upstream puts getRenderBoundingBox() on the block entity and
  the renderer reads it, which is Forge-only. Vanilla 1.18.2 has neither hook, so
  the method is currently a plain (non-override) helper on the renderer with NO
  effect until verified in game. Large statues may be culled when the core block
  leaves the frustum. Flagged for the next in-game pass rather than guessed at.
- new EntityMaid(level) does not exist (Mob's constructor takes the type), so
  renderers build throwaway entities through InitEntities.MAID.create(level).
- onBlockExploded -> wasExploded (runs before the block becomes air, so the block
  entity is still readable -- the same substitution the altar already uses).
- initializeClient (clay-coloured hit/destroy particles) has no counterpart, so
  statues and kits show stone-ish particles.
- Forge's IItemRenderProperties -> BuiltinItemRendererRegistry + the existing
  "parent": "builtin/entity" in models/item/garage_kit.json.
- The advancement trigger TriggerType.CHISEL_STATUE is not wired yet: the trigger
  subsystem is still incomplete in this port (already listed under known issues).
- getCloneItemStack takes (BlockGetter, BlockPos, BlockState) here, not the
  1.19-style (BlockState, HitResult, BlockGetter, BlockPos, Player).

Also in this commit: the creative tab no longer contains two copies of the
manual. Patchouli's ItemModBook#fillItemCategory already adds the book because
book.json declares creative_tab = touhou_little_maid.main, and MAIN_TAB.appendItems
runs that very method over every item; the extra CreativeTabCompat.appendBook call
was pure duplication, so it and the class are gone.

Book: chisel_and_statues + garage_kit restored, altar recipe craft_chisel added
with c: tags, validate-book.ps1 knows chisel / garage_kit / statue.
